# 프로토콜과 개발

[KS X 4506-9](https://standard.go.kr/KSCI/api/std/viewMachine.do?reformNo=01&tmprKsNo=KS_X_NEW_2015_1879&formType=STD)과 실제 장치 시험을 기준으로 구현했습니다.
예약 코드는 상세절 7.12의 `46`을 사용합니다. 요약표와 코드가 다릅니다.

## 방 주소

| 방 | 제어 주소 | 상태 비트 | 설정/현재 온도 인덱스 |
|---|---|---|---|
| 거실 | `11` | `01` | `10 / 11` |
| 방1 | `12` | `02` | `12 / 13` |
| 방2 | `13` | `04` | `14 / 15` |
| 방3 | `14` | `08` | `16 / 17` |

인덱스는 0부터 시작합니다. 상태 필드: 난방 `[06]`, 외출 `[07]`, 예약 `[08]`.
주소와 상태 비트는 다릅니다. 전체방 난방은 `11 → 12 → 13 → 14` 순서로 제어합니다.
방 값 `0F`를 쓰는 일괄 난방 명령은 사용하지 않습니다.

## 패킷

```text
상태 조회: F7 36 0F 01 00 CF 0C
방별 제어: F7 36 [주소] [명령] 01 [값] [XOR] [SUM+XOR]
명령: 43 난방 / 44 온도 / 46 본체 예약 / 47 메인 운전모드 / 50 전원
```

`01`은 데이터 길이입니다. 체크섬은 XOR, `(SUM + XOR) & FF` 순서입니다.

이 조절기는 `43 01 00`을 보내면 외출로 전환합니다.
난방 ON은 `43 01 01`, 전원 OFF는 `50 01 01`을 사용합니다.
OFF는 난방·외출·예약 비트가 모두 꺼졌는지 확인합니다.
`50`은 [참고 구현의 전원 명령](https://github.com/hkc321/smartthings-device-example/blob/7775a4dfded181bb5f0fc313838d71d68c01dad4/thermostat/main.c#L446)이며, KS 표준 명령과 구분합니다.
온도는 하위 7비트가 정수, 최상위 비트가 0.5℃입니다.
현재온도는 표준 해석이며 실제 표시값과 대조하지 않았습니다.
HA 온도 선택 범위는 UI 제한이며 장치 한계값은 아닙니다.

## 운전모드

| 응답 종류 | 난방+온수 | 온수전용 |
|---|---|---|
| 상태 조회 `81`의 `[09]` | `00` | `01` (`0F`도 수용) |
| 모드 명령 응답 `C7`의 `[09]` | `01` | `0F` |

메인 조절기의 실제 전환으로 확인했습니다. RAW 값은 그대로 보존합니다.
다른 값은 알 수 없음으로 표시합니다. 온수 OFF라는 기능은 제공하지 않습니다.

모드는 메인 주소 `11`만 제어합니다. 난방+온수 복귀는 `47 01 00`에 이어
메인 난방 ON(`43 01 01`)을 보냅니다. 거실 난방이 켜지며 다른 방 설정은 유지됩니다.

## 통신과 검증

- 방별 온도 20→21→20℃, 난방·본체 예약 ON/OFF를 실제 시험했습니다.
- 전원 OFF는 네 방에서 확인했으며, 방1은 실제 화면 꺼짐도 확인했습니다.
- TCP 연결을 잠깐 유지하고 명령 사이 0.2초, 완료 후 0.4초 대기합니다.
- 최종 조회를 최대 3회 수행합니다. 쓰기 명령은 자동 재전송하지 않습니다.
- 조회 실패 시 unavailable, 정상 조회 시 복구합니다. 통신은 직렬화합니다.
- 반복난방은 10초마다 검사하고 재시작 시 저장된 주기를 복구합니다.
- 시간 변경은 다음 검사에 반영됩니다. 정상 통신 시 종료 지연은 약 10초입니다.
