# EW41 Boiler for Home Assistant

![EW41 Boiler](custom_components/ew41_boiler/brand/icon.png)

EW41 TCP로 거실·방1·방2·방3 난방과 온도를 제어하는 Home Assistant 커스텀 통합입니다.
VCM-20T/NRM-20S 환경에서 시험했습니다. HA OS에서 별도 서버나 MQTT 없이 동작합니다.

## HACS 설치

Home Assistant Core 2025.6 이상과 HACS가 필요합니다.

1. HACS → 오른쪽 위 ⋮ → 사용자 지정 저장소.
2. `https://github.com/BBulMushroom/VCM-20T-EW41-homeassistant-boiler`를 **Integration**으로 추가.
3. **EW41 Boiler** 다운로드 → Home Assistant 재시작.
4. 설정 → 기기 및 서비스 → 통합 구성요소 추가 → **EW41 Boiler**.
5. EW41 IP와 포트를 입력합니다. 기본값은 `192.168.0.22:8899`입니다.

기본 응답 timeout은 2초, 조회 간격은 10초입니다. 온도 선택 범위 기본값은 10~30℃,
단위는 0.5℃입니다. 온도 범위는 UI 제한이며 장치가 허용하는 한계값으로 검증한 것은
아닙니다. 통합 옵션에서 조정할 수 있습니다. 최초 등록은 조회만 수행합니다.

수동 설치 시 `custom_components/ew41_boiler`를 HA의
`/config/custom_components/ew41_boiler`에 복사하고 재시작하세요.

## 제공 기능

| 엔티티 | 기능 |
|---|---|
| 방별 온도조절기 4개 | 목표온도, 현재온도, 난방 ON/OFF |
| 방별 난방 스위치 4개 | 난방 ON/OFF |
| 전체방 난방 스위치 | 4개 방을 순차 제어 |
| 방별 본체 예약 스위치 4개 | 본체에 저장된 예약 운전 켜기/끄기 |
| 운전모드 선택 | 난방 + 온수 / 온수전용 |
| 새로고침 버튼 | 즉시 상태 조회 |
| 진단 센서 | RAW 응답, 난방·운전모드 값, 예약 상태 |

본체 예약 스위치를 끄면 해당 방은 일반 난방으로 돌아갑니다. 난방 ON/OFF를 직접
변경하면 본체 예약이 해제될 수 있습니다. 예약 운전은 일반 난방 비트가 OFF여도
작동할 수 있으므로 본체 예약 스위치를 함께 확인하세요.

## HA 반복난방 자동화

본체 예약의 반복 간격·가동 시간은 온도조절기에서 설정합니다. 표준에는 예약 ON/OFF만
있으며 시간 설정 명령은 없습니다. HA에서 시간을 자유롭게 설정하려면 아래
**EW41 방별 HA 반복난방** 블루프린트를 사용하세요.

1. 설정 → 기기 및 서비스 → 도우미에서 해당 방의 **토글** 하나를 만듭니다. 처음에는 OFF.
2. 같은 화면에서 **날짜 및 시간** 도우미를 만듭니다. 날짜와 시간 모두 포함하세요.
3. 설정 → 자동화 및 장면 → 블루프린트 → 가져오기에 아래 주소를 입력합니다.

```text
https://github.com/BBulMushroom/VCM-20T-EW41-homeassistant-boiler/blob/main/blueprints/automation/ew41_boiler/repeat_heating.yaml
```

4. 블루프린트로 자동화를 만들고 같은 방의 온도조절기, 본체 예약 스위치, 도우미 2개를
   선택합니다. 간격·가동 시간을 설정합니다. 기본값은 **2시간마다 10분**입니다.
5. 대시보드에서 주기와 시간을 바꾸려면 숫자 도우미 2개를 만듭니다. 주기는 1~24시간(간격 1, 기본 2), 가동 시간은 1~59분(간격 1, 기본 10)으로 만들고 블루프린트의 선택 항목에 연결합니다. 해당 도우미를 대시보드에 추가하면 자동화를 편집하지 않고 시간을 바꿀 수 있습니다. 연결한 도우미의 값이 위 고정값보다 우선합니다. 변경은 다음 10초 검사에 반영되며 현재 주기의 시작 시각은 유지됩니다. 가동 시간을 분 단위로 내림하지 않으며, 정상 통신에서 종료 명령은 설정된 시간 이후 최대 약 10초 뒤 전송됩니다.
6. 토글을 켜면 첫 가동이 시작됩니다. 토글을 끄면 난방을 종료합니다.

간격은 **가동 시작부터 다음 가동 시작까지**입니다. 2시간/10분이면 10분 난방하고
나머지 110분은 OFF입니다. 목표온도는 방별 온도조절기의 설정을 따릅니다.
본체 예약은 자동 해제하여 중복 운전을 피합니다. 각 방에 별도 자동화를 만들 수 있습니다.
토글 도우미를 대시보드에 추가하면 반복난방을 쉽게 켜고 끌 수 있습니다.

10초마다 그리고 HA 재시작·통신 복구 시 저장된 시작 시각으로 현재 주기를 계산합니다.
자동화 자체를 비활성화하기 전에는 토글을 먼저 끄세요. 수동 난방도 토글을 끈 뒤
사용하세요. HA 정지나 EW41 통신 장애 동안은 종료 명령을 보낼 수 없습니다.
이 방식은 제조사 본체 예약의 난방수 제어와 동작이 다를 수 있습니다.

## 실제 장치에서 확인한 프로토콜

[KS X 4506-9 온도조절기 표준](https://standard.go.kr/KSCI/api/std/viewMachine.do?reformNo=01&tmprKsNo=KS_X_NEW_2015_1879&formType=STD)의
구조와 실제 시험을 대조했습니다. 요약표와 상세절에서 예약/외출 코드가 뒤바뀌어
있으므로 상세절 7.12와 실제 시험 결과를 사용합니다.

| 방 | 제어 주소 | 상태 비트 | 설정/현재온도 인덱스 |
|---|---|---|---|
| 거실 | `11` | `01` | `10 / 11` |
| 방1 | `12` | `02` | `12 / 13` |
| 방2 | `13` | `04` | `14 / 15` |
| 방3 | `14` | `08` | `16 / 17` |

인덱스는 0부터 시작합니다. 난방 상태는 `[06]`, 외출은 `[07]`, 예약은 `[08]`입니다.
제어 패킷은 `F7 36 [주소] [명령] 01 [값] [XOR] [SUM+XOR]` 구조입니다.
주소와 상태 비트는 서로 다릅니다. `01`은 데이터 길이입니다.

4개 방의 온도 20→21→20℃, 난방 OFF→ON, 본체 예약 ON/OFF를 실제 시험 후 복원했습니다.
`43`은 난방, `44`는 온도, `46`은 본체 예약입니다. 온도는 하위 7비트 정수와 최상위
비트 0.5℃로 해석합니다. 현재온도는 표준 해석이며 물리 표시값과 직접 대조한 것은 아닙니다.

전체방 제어는 거실→방1→방2→방3 순서이며 방 값 `0F`를 넣은 일괄 제어를 사용하지
않습니다. TCP를 잠깐 유지하고 방 사이 0.2초, 완료 후 0.4초 대기합니다. 목표 상태가
늦게 보이면 조회를 최대 3회 수행하며 쓰기 명령을 무조건 반복하지 않습니다.

메인 조절기를 직접 전환하며 확인한 **상태 조회 응답** `[09]`는 `00 = 난방 + 온수`,
`01 = 온수전용`입니다. `0x47` 명령의 **응답**에서는 `01 = 난방 + 온수`,
`0F = 온수전용`이 관측되어 프레임 종류에 따라 구분해 해석합니다. 조회에서 관측된
`0F`도 온수전용으로 표시하며 다른 미확인 값은 알 수 없음으로 남깁니다.
RAW 값은 변환하지 않습니다. 온수 OFF라는 기능이나 이름을 사용하지 않습니다.

운전모드는 **메인 조절기(거실 주소 `11`)만** 제어합니다. 방1~방3 조절기에는
온수전용 기능이 없으므로 모드 명령을 보내지 않습니다. 난방 + 온수로 돌아갈 때는
`47 01 00` 명령만으로 조회 상태가 복귀하지 않아, 실제 검증된 메인 난방 ON
명령(`43 01 01`)도 보냅니다. 따라서 **거실 난방이 ON**이 되며 다른 방의 난방과
설정온도는 유지합니다. 명령 응답만으로 성공으로 처리하지 않고 최종 조회로 검증합니다.

최종 조회로 성공 여부와 실제 상태를 반영합니다. 조회 실패 시 unavailable,
정상 조회 시 복구합니다. 여러 엔티티의 통신은 직렬화됩니다. 화염 가동은 추측하지 않습니다.

## 문제 확인 및 개발

- 등록 주소는 EW41 주소입니다. HA OS VM에서 해당 TCP 포트에 접근할 수 있어야 합니다.
- 다른 캡처 프로그램이 EW41 연결을 점유하면 종료하세요.
- 설정 → 시스템 → 로그에서 `ew41_boiler` 오류를 확인하세요.
- 온수전용 전환은 방별 난방 표시와 별도로 전역 운전모드를 확인하세요.

```sh
python -m unittest discover -s tests -v
```

모의 HA API로 엔티티·설정·통신 직렬화를 검증하고 실제 패킷 기반 회귀 테스트를 제공합니다.
실제 HA 로딩과 자동화 스키마 검증은 설치 환경에서도 확인해야 합니다.
수정 시 `manifest.json` 버전을 올려 HACS에서 업데이트하세요.

재사용 TCP API는 `protocol.py`의 `EW41Client`입니다. `get_status()`, `set_room()`,
`set_all_rooms()`, `set_temperature()`, `set_reservation()`, `set_hotwater_only()`,
`set_heating_hotwater_mode()`를 제공합니다.
